# evnx v0.10.3 — the cross-command release

**Released 2026-10-17.** 20 pull requests since v0.10.2 (#166–#185), plus the release PR.

`CHANGELOG.md` carries the full list, with a *Breaking, at a glance* section first.
This file is the why: what kept going wrong, how it was fixed once rather than
eleven times, and how each fix is held in place.

---

## Why this release exists

0.10.1 reviewed `init`; 0.10.2 reviewed `add`. The reviews of the other nine
local commands and the cloud commands were done in the same way — every command
run against a real build, every documented invocation tried — and they kept
finding **the same defects in different places**:

- files that hold secrets written with the umask's 0644, so readable by everyone
  on the machine (`convert -o`, `template`, `sync`, `backup`, `restore`, …);
- secret values printed or committed: `diff --format patch` printed every value,
  `sync`'s "actual values" choice and `add custom` put live keys into the
  committed `.env.example`;
- values cut short when written back into a `.env` — `"My App # prod"` came back
  as `My App`;
- exit codes that meant different things in different commands, so a CI gate
  could read "could not run" as "nothing found";
- notices and banners on stdout, so `spec init --stdout > .evnx.toml` produced a
  file nothing could read.

Fixing each where it was found would have meant eleven slightly different fixes,
which is how most of these defects arose. So this release puts each rule in one
shared module, moves every command onto it, and then fixes what each command
had left.

## How it was held in place

Before any shared code changed, **every reviewed command's training demo became
a test** (#166): 140 scenes across 11 commands, each with a golden file. A scene
that shows a defect says `KNOWN I-nnn`; the fix flips it to `FIXED`, and the
golden diff is the review. Nothing in this release changed a command's output
without a golden moving on purpose.

The final run, against the released 0.10.2:

| | |
|---|---|
| Demo scenes, new binary, run twice | every check passes; the two runs are identical |
| Lines of output that differ from 0.10.2 | 1,981 across 11 commands |
| Checks 0.10.2 fails | **34**, across 8 commands, each naming the issue it fixes |
| Tests | 1,732 passed, 0 failed |

## The shared rules

| Module | One rule for | Found as |
|---|---|---|
| `core::safe_write` | every file evnx writes: temp file + rename, 0600 for anything holding values, an existing file keeps its mode, a symlink is written through | `convert -o` 0644 (I-081); `sync` replacing a symlink and resetting a mode (I-122, I-123) |
| `core::gitignore` | is `.env` protected, and adding the rule | doctor `--fix` reporting repairs it had not made |
| `core::classify`, `core::mask` | "is this a secret" (by name, at two strictness levels, and by value) and how one is shown | `diff` printing secrets (I-071, I-076), `sync` copying them (I-113) |
| `core::verdict` | 0 clean · 1 findings · 2 no verdict | I-116, I-074, I-106 |
| `utils::term`, `-q` | stdout is the product, stderr is the commentary; `-q` silent on success | I-176, I-007 |
| `core::envfile` | writing a `.env` line and deciding whether text is a `.env` | I-114, I-145 |
| `core::shell`, `core::args`, `core::envsource` | quoting a shell word, checking a name, reading the environment | `migrate` printing commands that ran parts of a value (I-102) |
| `cloud::client::api_path` | every cloud request path | a vault name with `/` or `..` reaching another resource (I-217) |

Architecture tests fail the build if a second definition appears of the
placeholder, masking and secret-name rules, the `.env` line writer, the cloud
path builder or the credential guard, or if a command exits the process itself
instead of returning a verdict.

## Command fixes worth knowing about

- **`scan` reads every file in a folder.** It read only files whose extension
  was on a list, so `config/id_rsa.pem` was never opened and the scan exited 0.
  Binary and over-1 MiB files are skipped, and the scan says how many.
- **The `evnx-sync` pre-commit hook works.** It failed with "not a terminal" on
  any drift and "file not found" on every fresh clone. It now runs
  `sync --check --skip-without-env`. `sync --check` also works in CI, which has
  no `.env`: it checks the template against the spec.
- **`sync --direction reverse` keeps the template's values** instead of
  regenerating them from the name.
- **`spec init --merge`** replaces `--force`, which wrote a file TOML refused.
- **`doctor`** no longer aborts on a Pipenv or `poetry.lock` project.
- **`init`**: `--detect` finds the database an `sqlx` project uses (from its
  features), and `--from-source` no longer proposes values Vite and Astro fill
  themselves (`import.meta.env.DEV`, `MODE`, `SITE`, …).
- **`convert` refuses names that collide after `--transform`**, instead of
  silently dropping one.
- **Cloud:** API tokens can no longer change the account or delete vaults (also
  enforced by the server — see below); `cloud run` keeps `LD_PRELOAD`-style names
  and its own token out of the child; malformed input is refused before any
  request.

## Upgrading

Read *Breaking, at a glance* in the CHANGELOG. The changes most likely to touch
a script:

1. A script that saves `evnx diff --format patch` and applies it must add
   `--show-values`.
2. A script that reruns `evnx convert -o FILE` must add `--force`.
3. A script that reads the banner from stdout must read stderr.
4. A CI step that treated exit 1 from `sync --naming-policy error` as drift now
   gets 2.
5. `evnx spec init --force` → `evnx spec init --merge`.
6. A large repository's `evnx scan .` reads more files and may find more.

## The server side

Two evnx-server changes go out with this release and **must be deployed first**
(`docs/RELEASING.md`, step 1):

- **SV-1** — deleting a vault or a version, changing membership and re-keying
  need a signed-in user; an API token gets 403 (I-220).
- **SV-2** — a token's lifetime (1–3650 days) and name (1–64 characters) are
  validated before anything is written (I-205, I-206).

Both were exercised end to end against a local server with the 0.10.2 CLI and
this one before release.

## Not in this release

- The per-command documentation pass (task 15): the guides on evnx.dev that
  these changes touched are updated alongside; the full review of every guide's
  invocations is separate.
- Issues still printed as `KNOWN` by the demo locks: 69, each with its decision
  in its command's review. They are open on purpose, not forgotten.
